# Optimization Experiments Log

This is the maintained ledger for BaseLayer performance experiments. Update it when a new optimization is tested, whether it works or not. The point is to keep the active search space focused and avoid rerunning known dead ends.

## How To Use This File

- Add every meaningful experiment with date, profile, workload, data source, result, and decision.
- Mark status as `keep`, `reject`, `revisit`, or `experimental`.
- Link to raw artifacts or run-data paths whenever possible.
- Do not promote an optimization to the main path unless it improves total lifecycle or a clearly named product metric without breaking compatibility.
- Do not compare invalid benchmark semantics against leaderboard-style results.

## Current Main Baseline To Preserve

For BrowserArena-style AWS bare-metal density:

- Runtime: Firecracker + `chromium-headless-shell`
- Guest: `1 vCPU`, `1024 MB`
- Navigation: `domcontentloaded`
- Image/media blocking: off
- Delete behavior for latency runs: async
- Valid Composer 2 async c24 result: `24/24`, lifecycle `4349 ms`, goto `3788 ms`
